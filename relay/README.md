# HTTPS-комнаты TV Quiz

Новый транспорт нужен для сетей, в которых прямой WebRTC-канал не открывается.
Ведущий и телефоны отправляют сообщения HTTPS-запросами и получают входящие
пакеты опросом раз в 400 мс. PeerJS нужен только для старых QR без префикса r1-.
Каталог, правила, генерация вопросов и подсчёт очков остаются на ведущем.

`worker.mjs` — Cloudflare Worker без зависимостей; `drizzle/` — схема D1.
В Sites сервер зарегистрирован как «TV Quiz — сервер игровых комнат».
Ожидаемый адрес: https://tv-quiz-rooms.cleverpineapple8.chatgpt.site .
Приватная публикация сервера не делает его доступным анонимным игрокам:
до переключения доступа и проверки публичного API **не объединять клиент в main**.

## Данные и ограничения

- Ссылка комнаты содержит случайный 192-битный код приглашения. Вход по нему
  разрешён участникам; прав ведущего этот код не даёт.
- Отдельные случайные bearer-токены ведущего/участников хранятся в памяти
  браузера. В D1 сохраняются их SHA-256, а не сами токены. Токен ведущего
  не входит в QR, исходники или localStorage.
- Телефон отправляет сообщения только ведущему и читает только собственную
  очередь. Тексты ответов других игроков не доступны через API.
- Имена, аватары, игровые сообщения и ответы временно проходят через сервер
  Sites/Cloudflare. Это HTTPS, не сквозное шифрование. Пароли/почта не нужны.
- Комната доступна до двух часов. При закрытии ведущим удаляются комната,
  игроки и сообщения. Заброшенные просроченные записи удаляются при следующем
  создании комнаты; доступ к просроченной комнате закрывается сразу.
- До 24 игроков, 200 активных комнат, 12 000 событий на комнату, запрос до 64 КиБ.
  Это прототип для небольшой нагрузки, не сервис с обещанной доступностью.
- Каждые пять секунд стороны посылают служебный сигнал. Через 30 секунд
  отсутствия сигналов соединение закрывается. Повтор отправки идемпотентен;
  при кратком отказе HTTP выполняются ограниченные повторы.
- Сохранение счёта после перезагрузки ведущего/повторного входа не добавлено.

## Проверки и сборка

`node scripts/test_relay_api.mjs` проверяет схему в настоящем SQLite, права
ведущего/игроков, изоляцию комнат, повтор сообщений, ограничения и удаление.
`node scripts/test_https_game.cjs` запускает Worker через локальный HTTP-адаптер:
WebRTC и PeerJS отключены, два браузерных телефона проходят вход/готовность,
запуск с клавиатуры, ответы, счёт 0/1, итоги и закрытие комнаты.
Это не подмена игровых ответов и не тест двух WebRTC-клиентов на одном ПК.
После публикации проверяем вход по действующему QR, готовность и ответы двумя браузерными клиентами. Конкретную модель устройства проверяем при сообщении о сбое на ней.

`echo '{}' | node scripts/test_deployed_relay.mjs` проверяет опубликованный
API: создание/вход, обмен сообщениями, CORS, права и удаление. Для закрытого
предпросмотра существующий токен Sites передаётся только через stdin;
в клиентском коде и репозитории этого токена нет.

Для публикации Sites копирует `worker.mjs` в `dist/server/index.js`, а исходные
миграции — в `drizzle/`. Манифест `.openai/hosting.json` серверного checkout:
`project_id` берётся из существующего Sites-проекта, `d1` — `DB`, `r2` — null.
Рабочий checkout сервера: `H:/TV-Quiz/.local-tools/quiz-relay-site`.
GitHub хранит канонические исходники, Sites — зеркальный серверный пакет.
Секреты доступа к репозиторию Sites не входят в этот репозиторий.
